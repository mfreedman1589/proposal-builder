# Proposal Builder

A Streamlit app that assembles polished, client-personalized Premion CTV/OTT proposal decks from a form, by deleting unselected slides from a master `.pptx` and filling the retained template slides. The Claude API drafts a first pass at the form from pasted meeting notes and powers the audience-segment finder; Supabase holds the master deck, the rate card, the audience catalog, the case study vault and every logged proposal.

**Stack:** Streamlit (form + UI), python-pptx (deck assembly/fill), pdfplumber (audience catalog PDF parsing), Anthropic Claude API (`claude-sonnet-4-6` -- draft-from-notes + audience suggestions), Supabase (Postgres + private storage buckets), PowerPoint over COM (local rendering and validation only).

## Where things are written down

This file is loaded into context at the start of **every** session, so its size
costs tokens on every turn. It carries the rules and the traps — not the
reasoning behind them, and not the history.

| Doc | What's in it |
| --- | --- |

| `DECISIONS.md` | Why each rule exists — the incident, the measurement, the alternative that was tried and abandoned. Every rule below marked → `DECISIONS.md` has its full original wording there. |
| `HISTORY.md` | What was built in what order, and what each round of live testing turned up. |
| `BACKLOG.md` | Living list of queued feature work — what each item is, why, and what's already decided. **Record a new feature idea here as it comes up**, rather than losing it or re-litigating it from scratch next time it's raised. |
| `SLIDE_KEYS.md` | Slide tagging: how a `key:` label works, how to correct one, how the update page gates on it. |
| `DEPLOYMENT.md` | Streamlit Cloud: secrets, deploy order, schema-before-push, warm-process staleness. |
| `proposal_builder_build_spec.md` | The full spec (data model, form fields, slide map, phasing). Read it before making non-trivial changes. |
| `master_v1_1_changelog.md` | The master deck's token conventions and what changed from v1. |
| `geo_targeting_roadmap.md` | Geo/zip/market targeting: what's built, what's researched, the avails-PDF import, the `audience_usage` analysis. |
| `market_profiles_index.md` | The extracted market viewer profiles. |
| `master_deck_slide_keys.md` | Generated slide → title → key reference. A convenience copy; the speaker notes are the source of truth. |

**Keep this file under 150k characters, and prefer well under it.** When a note
here grows past the rule into the story behind it, move the story to
`DECISIONS.md` (or `HISTORY.md` for build history) and leave one line naming the
rule and its guard. When a rule ends up enforced by a test, the line here names
the rule and the test, and the reasoning belongs in that test's docstring.
Adding to this file is not free — the default is to move something out, not to
append.

## Key conventions

### Data, the backend and the rate card

- **All Supabase access goes through `db.py`, and every loader falls back rather than raising.** Nothing else imports the supabase client. Every *read* returns `(value, warning)` — real data or the local fallback, plus `None` or a plain-language sentence the caller shows with `st.warning`. **A fallback is never silent, and a loader never raises for an unreachable backend**: the form has to render offline, on a broken URL, on a paused project, and in local dev with no secrets. *Writes* return `(ok, error)`; a failed `log_proposal` is a caption, not an error. A loader returns `None` rather than `[]` when the caller should fall back. Catalog reads are paged past PostgREST's 1000-row default. What falls back to what: master deck → the checked-in `.pptx`; rate card → `FALLBACK_PRODUCTS`/`FALLBACK_SPORT_CPM` in `app.py` (**edit rates in Supabase, not there**); audience catalog → parsing the brochure PDF. → `DECISIONS.md`
- **DDL is not something the app can do, and schema goes before code.** Statements live in `supabase_schema.sql`, are idempotent, and are pasted into the Supabase SQL editor by hand. The sequence is **run the SQL → push → confirm the live app is serving the new code**, rebooting it if it isn't — a push that succeeded is not proof the new code is running. `setup_supabase.py all|deck|products|audiences|case_studies|slide_vault|proposal_files` does everything the client can; `products` is a **bootstrap, not a sync** (re-running it overwrites rate edits made in Supabase). Every table has RLS enabled with no policies; the app is server-side on the service key. → `DEPLOYMENT.md`
- **Sports are products.** `products` rows keyed `sport:<sport_key>` with `display_group='sports'` carry the per-package ratecard rates, so `line_product_spec` resolves a sports line's label and CPM through the same one lookup as everything else. `line_type` is `rate`/`flat` (matching the media-plan grid's Type column); the old premion/am/broadcast value is `display_group`, which is what it always actually meant. `targeting_copy` is the product's own column rather than two hardcoded prefix rules, matched by tactic-name prefix (longest first, since product labels are prefixes of one another) so a drafted row with a label appended still picks it up.
- **The audience catalog lives in Supabase's `audiences` table; the brochure PDF is the local fallback, not the live source.** `audience_catalog.load_audience_catalog()` reads `db.fetch_audiences()` first; `_parse_pdf_catalog()` (segment/category/subcategory/RFP-selectable, RFP-selectable detected from the highlight *rectangle*, a fill shape, not a text colour) only runs when Supabase is unreachable. If the brochure is replaced, re-verify against page 2's own roster and read the two PDF-geometry gotchas first. → `DECISIONS.md`
- **The YTD usage workbook Matt refreshes periodically is an uploadable, versioned data source, the `deck_versions` pattern applied to audience data — "Update audience usage."** `audience_usage_import.py` (pure, no DB) parses the workbook (Segment Name / Delivered Impressions, one row per booked stack; "No Data Targeting" dropped) and **merges** the result into the catalog rather than replacing it: components are split on commas (a stack is an AND-list, same derivation `audience_usage_ytd.csv` always used), folded through `market_profiles._normalize` before merging so a case/punctuation variant can't split one segment's history in two, and categorized from their own prefix or, for a `CUSTOM`-prefixed one, a second prefix embedded in the name (`"CUSTOM FOOD Grocery Delivery Services"` → `FOOD`) — never guessed past that; an unrecognized prefix is reported uncategorized. **A component that normalizes to an existing catalog segment keeps that segment's exact spelling, category and `rfp_selectable`** (the brochure is authoritative for RFP-selectable, which `custom_segment_count` depends on) **and only gets its usage numbers refreshed; a component the catalog lacks becomes a new row, `rfp_selectable=False`** — the safe default. **`CLT`-prefixed components (a client's own first-party data, never selectable for anyone else) are excluded from the catalog outright**, and from `audience_evidence`'s booking-evidence index too (`_split_parts`/`evidence_for` both filter them, so one can never surface as a suggested pairing) — the raw `audience_usage` transcript keeps the full original stack text regardless, since exclusion is enforced at every consuming boundary, not by rewriting the historical record. `audiences.metrics` is a jsonb bag (`{"impressions": N}` today) so a second ranking metric (a response rate, later) is a new key, not a migration; `prioritize_catalog` and the finder's familiarity line both rank by impressions now, not `times_used` — **stack count is kept where the evidence panel is about precedent** (co-occurrence, pairings) rather than volume. `db.activate_audience_usage_version` does the actual rebuild (unlike `activate_deck_version`, a bare flag flip won't do — nothing else re-derives these tables on a refresh); the admin page parses and reports gained/collided/uncategorized/excluded-CLT counts client-side before any write, the same upload → validate → gate → activate shape `render_update_master_deck` uses. Guards: `tests/test_audience_usage_import.py`, `tests/test_update_audience_usage_page.py`, `tests/test_audience_evidence.py`'s CLT section.
- **A second class of exclusion, same treatment as CLT, for components with no CLT prefix: one advertiser's own retargeting/address-list pool.** `is_client_pattern` catches four structural forms mechanically (`WEB RT`, `LOCATION RT`, `..._RFPID-..._RT`, an "Address List" suffix — a search, not an anchored match, since the real data has both `"WEB RT- X"` and `"X _Web RT"`); verified against a real 106-component markup pass at zero false positives, catching 29 of 41 confirmed cases automatically. The rest — a bare client/campaign name with no structural marker (`"CUSTOM Out West"`) — can't be told apart from a real custom segment by pattern, and live in `audience_component_overrides.csv` (`action=exclude_client`) instead, alongside three more manual actions the same registry holds: `categorize` (added `B2B` and `LEGAL` as categories this way — confirmed `LEGAL` doesn't collide with the brochure's own `FIN Legal Services`, a different segment entirely, still `FIN`, untouched), `split` (an OR-joined compound that's really two components, each getting the FULL stack/impressions attribution of the whole phrase — the same rule two comma-separated components in one real stack already follow, never divided), and `leave_blank` (confirmed uncategorizable, so it stops re-surfacing in every future report). `load_overrides()` reads the registry automatically on every `derive_catalog_updates` call, so this is permanent pipeline behavior, not a one-time script — a future workbook needs a manual pass only for what the pattern and the existing registry both miss. `audience_evidence.py` gets its own copy of the mechanical pattern only (not the registry — importing it would pull in db.py/streamlit through `audience_catalog`, against that module's "no DB, no Streamlit" design), so the ~12 registry-only exclusions are catalog-scoped, not evidence-index-scoped — a known, explicit boundary.
- `.pptx` and `.pdf` files are gitignored (master deck, generated test output, source brochure) — never commit them. Secrets live in `.streamlit/secrets.toml` (gitignored) — `APP_PASSWORD` (shared-password gate) and `ANTHROPIC_API_KEY` (draft-from-notes + audience suggest, read via `st.secrets.get("ANTHROPIC_API_KEY")` at runtime). That file is fenced off hard: `.claude/settings.json` denies reading it via any tool, and the sandbox itself blocks even a blind existence/append check on it from this assistant — the user edits it directly.

### Deck assembly and slide selection

- **Slide map is always derived by scanning, never hardcoded.** `slide_map.py` opens the master deck and classifies every slide into a `condition_key` (e.g. `vertical:healthcare`, `vertical:healthcare:targeting`, `sport:nfl_playoffs`, `sport_viewership:nfl_playoffs`, `full_deck`, `transitional_divider`) by matching text anchors, with a small carry-forward default for undifferentiated divider slides. If the master deck is replaced with a new version, do **not** hand-patch slide numbers — update the anchor rules in `slide_map.py` if a new slide type needs one, then let it re-scan. This was a direct, hard-learned lesson from the v1 → v1.1 deck migration (slide count and positions shifted; a stale hardcoded map would have silently mis-assembled decks). Watch for anchor collisions with boilerplate footer text (e.g. "CONF" matching "confidential") — needles should be as specific as the real text allows.
- **A slide's `key:` label in its speaker notes beats the text anchors.** `slide_map.build_slide_map_from_prs` reads it first and falls back to anchors only for an untagged slide; matching is case-insensitive and whitespace-tolerant, and the **last** `key:` line wins. Anchors still run on every slide, because the carry-forward section default has to keep tracking. Correcting a mislabelled slide means editing its notes, not the code — which is exactly why the labels live in the deck. → `SLIDE_KEYS.md`
- **The "Update master deck" page blocks on a slide whose key came from carry-forward**, not on `key is None` — anchor classification always produces *some* key, so a naive gate would never fire. `_classify_all` reports a source per slide (`notes` / `anchor` / `carry`), and `carry` is a guess dressed as an answer. → `SLIDE_KEYS.md`
- **No part of the app depends on slide numbering.** Presets select by condition_key (`CORE_CONTENT_KEYS`, `STANDARD_FORCED_KEYS`), never by slide number — the old literal allowlist would have mis-assembled every deck after the first master update. **"Standard" forces the avails template in even when the form's toggle is off**, so targeting/avails mutual exclusion is enforced as a **post-processing step in `build_presentation`** based on which slides actually ended up kept, never on the toggle value alone: whenever the personalized avails template is present, the vertical's static Precision Targeting slide is dropped, in every preset. → `DECISIONS.md`
- Slide deletion works by removing the `<p:sldId>` from `presentation.xml`'s `sldIdLst` and dropping the corresponding relationship (`prs.part.drop_rel`) — python-pptx then automatically omits any part unreachable from the package's relationship graph on save, so orphaned slide parts clean themselves up. Reordering (e.g. moving the vertical stats slide to position 3) is the same idea: remove the `<p:sldId>` and `.insert()` it back at the target index.
- **No section dividers appear in a generated proposal, ever.** All ten classify as `slide_map.SECTION_DIVIDER_KEY` and `build_presentation` drops them as a post-processing step, not as an omission from `resolve_active_keys`. Each entry still carries a carry-forward default, which is what resolves the slides it introduces. → `DECISIONS.md`
- **Total TV drives the deck's branding on its own, with no extra toggle**, and the market picks every branded variant — cover, plan template, and the station's own schedule slide. Replacement is a **sweep in `build_presentation`**, and both markets' variants are swept unconditionally: a competitor station's branding in front of a client can't be allowed to survive a selection bug. **Three of the seven variants resolve from their notes label ALONE** (they are text-identical to what they replace), so a merge that drops speaker notes collapses them silently. Guards: `check_total_tv_by_market`; `tests/test_draft_regression.py` re-applies the labels after `copy_slide_into`. → `DECISIONS.md`
- **A sport contributes its package slide; the viewership chart is opt-in** via one deck-wide `products.live_sports.viewership` checkbox covering every selected sport. `sports.get("viewership", True)` is the one place a missing key means True — only proposals logged before the toggle existed carry none, and "Rebuild as presented" has to reproduce what the client received. Same shape as `vertical_attribution: None`: when a new selection field changes what a *rebuild* produces, the legacy value has to be the old behaviour, not the new default. → `DECISIONS.md`
- **"Working from an avails document" (`avails_mode`) is authoritative over everything downstream of it, not just the uploader — a real WAEPA find (2026-09-08).** With the toggle off, a proposal still: seeded a placeholder targeting group from a drafted audience (`apply_draft_to_form`'s seeding branch now checks `avails_mode` and, when off, routes the audience name to `unresolved_internal` instead of seeding); seeded a D2 placeholder row per target market (the D2 gate now reads `include_avails_template and avails_mode`); and kept `targeting_avails_template` in the deck even though `STANDARD_FORCED_KEYS` forces it in for the "standard" preset — `build_presentation` now drops any `TARGETING_AVAILS_KEYS` slide whenever `selections.get("avails_mode", True)` is False, the same drop-after-the-fact sweep shape as the Total TV/attribution sweeps below (and the report builder's delivery-set drop), placed before the mutual-exclusion check so a vertical's own static fallback can still surface. A `selections` dict with no `avails_mode` key (every caller that predates this) defaults True, unchanged. Hand-typing with the toggle ON and no document is still today's intended behavior — a placeholder row a rep fills by hand. Guard: `tests/test_avails_mode_authoritative.py`. → `DECISIONS.md`
- **Auto and travel sell their own attribution product (Polk Signals / Arrivalist), and it stands in for the generic line.** `assembly.VERTICAL_ATTRIBUTION` plus a per-vertical Section D checkbox (`vertical_attribution_auto`/`_travel`, checked by default) drives the slide *and* the Included-with-Campaign line. **Auto replaces the generic "Measure Sales Conversions" slide; travel doesn't** (`replaces_sales_slide`) — that asymmetry is deliberate, not an oversight. Matched by a text marker and swept in `build_presentation`, the same mechanism as the Total TV variants. → `DECISIONS.md`
- **A master deck is optimized on the way into storage, and blocked if it still won't fit.** `optimize_deck.py` re-encodes opaque PNGs as JPEG (~95MiB → ~48MiB against a 50MiB ceiling), leaves genuinely transparent images, vectors and embedded fonts alone, and **is idempotent — keep it that way**, since a deck round-trips repeatedly. `db.prepare_deck_for_upload` sits in front of every upload route and writes nothing (no file, no version row) when the optimized deck is still too big. Verify a new build with `--verify`. → `DECISIONS.md`
- **Case studies go immediately before the media plan slide, and the graft must happen before `personalize`.** The insert point is found by the `{{PLAN_TITLE}}` token — not by condition_key, which Total TV's plan variants broke — and `personalize` both consumes that token and clones the plan slide per option directly after the original. Nothing is ever included silently: vertical matches are pre-checked but always visible and overridable, off-vertical ones sit in an expander, and the `cs_pick_*` keys are deleted when the vertical changes. → `DECISIONS.md`
- **Slide duplication is how multi-option decks are built, and rIds are the whole trick.** `assembly.duplicate_slide` adds a slide from the same layout, deletes the auto-cloned placeholders, copies the shape tree and rewrites every relationship reference (`_remap_relationship_ids`), because rIds are **part-local**; the layout and notes-slide rels are deliberately excluded. **And a duplicated slide needs a partname nobody else is using** — after `build_presentation` has deleted most of the master, python-pptx's `slide{len+1}.xml` collides with a retained slide, **nothing raises**, the only symptom is a `zipfile` `UserWarning`, and one part silently overwrites the other. `_next_free_slide_partname` claims a genuinely free number first. Invisible to a synthetic test deck, whose slides *are* contiguously numbered. → `DECISIONS.md`
- **Token fill convention:** template slides carry `{{TOKEN}}` placeholders in run text. Fill by finding the run containing the token and doing `run.text = run.text.replace(placeholder, value)`. **Never assign `text_frame.text`** — it collapses all run-level formatting (font, color, size) on that paragraph. Multi-item content (bullet lists, table rows) is filled by deep-copying the tokenized paragraph/row XML element and inserting clones as siblings, then filling each clone the same way. See `fill_bullet_list` / `fill_table_rows` in `assembly.py`.

### The media plan and the form

- **A product toggle diffs the plan; it never rebuilds it.** Rows are added only for newly-selected products and removed only for deselected ones (`_seeded_tactics`, matched by prefix since a drafted row appends its own label); **every existing row is left alone**, drafted or dirty or otherwise. Additions are guarded by what's on the grid rather than by the stored list, because a draft and a rehydration both write rows without it. This is the second rerun path that silently zeroed drafted rows, which is why `check_post_draft_edits` tests the whole seller sequence — draft, toggle on, import, toggle off. **Premion Streaming TV is the one exception to this whole mechanism** — see "Targeting groups own their Premion Streaming TV line" below, `_seed_option_rows` forces it off before this diff ever runs. → `DECISIONS.md`
- **Targeting groups own their Premion Streaming TV line — the avails table is research, never an implicit seed list.** Every group defaults `include_in_plan=False` (`targeting_groups.new_group`, same shape as `color`/`color_locked`: a value plus "a rep broke this one out, stop auto-managing it" — `include_locked`), whether it arrived via an avails-PDF import, the Audience finder, or a hand-typed D2 row. A group's line exists if and only if the D2 grid's **Plan** checkbox column (first visible column, same `_cell_unchanged` fold-back discipline every other D2 column uses — the highest-risk line in the whole feature is `tg.new_group` losing `include_in_plan`/`include_locked` on a render that touched nothing) is ticked — one at a time, via **"Add all to plan"**, or pre-ticked by a draft (below). `reconcile_group_plan_lines` (app.py) is the single, idempotent owner: add a row for a newly-selected group, remove one whose group was deselected (silently if clean, **queued for confirmation if the row is dirty** — a hand-edited line is never discarded without naming the numbers and requiring **"Remove them and discard those numbers"**; **"Keep them on the plan"** just drops the queue), re-price selected clean rows against a stored allocation on request. All four D2 actions (a single tick, Add all, Clear plan lines, Remove/Keep) go through the SAME queue-then-apply-before-D2-reads-groups shape `apply_pending_color_cascade` already used — a button that both reads and writes `_pending_include_removal` inside its own `if st.button(...)` block reads it before that render's fold-back has run and writes it after, so the fold-back's own merge is already stale by the time the write lands (a real bug, caught by `tests/test_group_plan_selection.py`'s Keep/Remove flow going red before the buttons were moved onto the shared mechanism). Every **other** product (retargeting, AM, sports, fees, broadcast) is untouched by any of this and produces **one line for the whole campaign**, not one per group — never fanned out per targeting group to begin with; `_seed_option_rows` passes the single flat `default_geo`, not the per-group `plan_lines`, for anything that isn't Premion. Guards: `tests/test_group_plan_selection.py` (the mechanism, fold-back survival, idempotency), `tests/test_group_plan_order_invariance.py` (below), `tests/test_avails_pdf_wiring.py`.
- **Drafting selects from existing groups instead of inventing lines, and order stops mattering once real groups exist by the time selection is expressed.** `build_draft_prompt`'s `existing_groups` parameter (populated from `session_state["targeting_groups"]`) adds a prompt section — and three new schema keys, `group_selection`/`group_allocation`/`group_selection_reason` — **only when real groups already exist**; a no-groups draft's prompt, and every frozen tier-1 fixture, is byte-identical to before. `apply_draft_to_form` computes `groups_own_plan` once, from session_state as it stood **before** this draft, and when true **never writes `avails_seed_rows`/`targeting_groups` from the drafted audiences at all** (the fix for the bug that made import-then-draft destroy a real import's resolved `geo_def`/`resolved_zips` — line 3556's old wholesale overwrite). `match_groups_to_selection` resolves the model's `ids`/`match` phrases against exactly the three strings `plan_lines_from_groups` already derives per group (`tg.audience_label`, `tg.geo_label`, `group["name"]`) — **`geo_def["kind"]` is never read**, so selection is provably geo-kind-agnostic. Pre-selection never overrides `include_locked`. Disclosure is mandatory and routed, never collapsed: notes naming specific audiences → `unresolved` (client confirms); notes silent, everything selected → `unresolved_internal` (seller check); a `match` phrase that matched nothing → `unresolved`, quoted verbatim; a group skipped because locked → `unresolved_internal`. The stored `draft_plan_intent` (section `"media_plan"` in `DRAFT_KEY_SECTIONS`) keeps the **raw** selection criteria, not resolved ids — `apply_draft_plan_intent_to_new_groups` re-runs the matcher against whatever groups a **later** import produces, which is what makes draft-then-import converge with import-then-draft. **Known, accepted limitation:** a draft run before ANY avails work exists is never even asked about group selection (the prompt section requires real groups to list) and takes the old invent-lines-from-notes path; nothing retroactively reshapes those invented lines once a real import lands later — the normal workflow already pulls avails before drafting, so this is a rep working out of order, not a case worth a rebuild-and-carry mechanism. `apply_draft_plan_intent_to_new_groups` still says so plainly (an `unresolved_internal` note) when it detects the shape. Guards: `tests/test_draft_group_ownership.py`, `tests/test_group_plan_order_invariance.py` (the acceptance test: import→draft and draft→import-where-groups-already-existed converge on identical selected groups/lines/amounts, a redraft re-prices the same group ids rather than regenerating, and the reconciler is idempotent).
- **Whoever replaces state owns all of it.** A staleness guard that only discards stored state on *zero* overlap silently keeps a stale subset when old and new partly agree — which is the commoner case, and which shipped a deck whose totals row said two months while its Flight column said three. `apply_draft_to_form` writes `active_months` outright, and reads the form's own months via `form_flight_months()` where it has no say over the flight. **Partial agreement is the case a staleness guard must be tested against**; zero and total overlap both look correct. Guards: `check_drafted_months_survive_a_used_form`, `check_budget_ties`. → `DECISIONS.md`
- **A keyed widget's session_state entry beats its `value=` argument, so replacing the thing behind it loses data.** Once `option_name_0` exists holding "Option A", re-rendering `st.text_input(..., value="Kickoff", key="option_name_0")` keeps "Option A" — and because the option's name is read back *from* the widget, the drafted name is then written into the option dict and gone. It presented as a cosmetic glitch (only the *first* option was wrong, since option 1's key was new) but it was real data loss. Any structural replacement of the option list — a draft, an add, a remove — calls `bump_plan_options_generation`, and the generation is part of every per-option widget key (`option_name_{gen}_{idx}`), moving the widgets to fresh keys so `value=` is honoured again. Same device as the per-option editor `version`. Applies to any widget whose `value=`/`index=` is computed from replaceable state.
- **The flight's per-month model has one owner, `flight_month_ranges` (FLOW_REWORK_PLAN.md Phase 2)** — the successor to a keyed multiselect that used to ignore its own `default=` once session_state held a value, which is how a drafted flight once produced the label "TBD": the stored months were all invalid against the new range, the selection filtered to nothing. `flight_month_ranges` reconciles a stored per-month list against the current flight bounds with the same rule that incident settled: an empty intersection means the stored choice belongs to a different flight and resets to all-default; a partial overlap is real custom flighting (a skipped month, or one clipped to part of its span) and is kept, clamped into the new bounds rather than dropped. `form_flight_months` and the old inline duplicate in `main()` both collapse onto it now, so there's one reconciliation, not two independently-maintained copies of the same rule. → `DECISIONS.md`
- **The Targeting column carries the whole audience stack, and is per line.** `audience_stack()` joins *every* Campaign Specs Audience bullet, because silent truncation is the worse failure. `resolve_row_defaults` resolves Targeting three ways: the product's own `targeting_copy` when it has one; **the row's own copy, kept**, for an imported broadcast line (its Targeting and especially its Geo come from the Wide Orbit schedule and the station's call sign, and re-seeding the Geo would put a wrong DMA on a client's plan); otherwise the audience stack. All three call sites (`main`, draft, rehydration) must change together, since `default_targeting` feeds `_shared_fields_key`. Geography still uses `first_line()`. Guard: `tests/test_broadcast_e2e.py`, which makes an edit rather than reading a freshly seeded row. → `DECISIONS.md`
- **A plan row's Geo cell prefers the target markets over the Campaign Specs Geography narrative, not the other way around.** `geo_column_default(target_labels, geography_text, originating_label)` used to return Geography text whenever non-empty and only fell back to the joined target-market labels when it was blank — backwards, since Geography is sentence-length narrative prose and a plan cell needs a short market label. Real find (WAEPA, 2026-09-08): a plan row showed the full narrative instead of "Washington, DC, Baltimore." Fixed by swapping the precedence: target labels win whenever they exist; Geography text is the fallback, for the residual case where target-market-name matching itself fails and no labels resolve at all — that fallback is deliberately still narrative text, a known, unfixed edge case. Guard: `tests/test_geo_defaults.py`. → `DECISIONS.md`
- **A proposal carries 1–3 media plan options, and one option must render exactly like no options at all.** `personalize` clones the plan template per extra option and fills each independently, so the plan's scalar tokens are filled per slide, not in the deck-wide pass. The option name is appended to the plan title only when there's more than one. **The plan slide title never echoes the client name twice** — the master deck's own template composes `"{{CLIENT_NAME}} {{PLAN_TITLE}}"` as one run, so a drafted `proposal_title` that already opens with the client name doubled it ("WAEPA WAEPA CTV Strategy"); `option_plan_title` strips a leading, case-insensitive echo (an optional `-`/`:` separator too) before composing, falling back to the untouched title if stripping would empty it. Guard: `tests/test_plan_title_dedup.py`. → `DECISIONS.md`
- **Impressions and Cost are bidirectional, resolved by a per-row driver flag.** `media_plan_driver` records which side the user last typed into and `recompute_row` derives the other. A **CPM edit deliberately does not change the driver**. Drafted rows drive from cost, since the allocation amounts are already group-rounded to tie to the budget. The preview and the deck read `Cost` straight off the row rather than recomputing it — every row on the grid is **net**; the agency gross-up is applied once, at display/deck time, never here (see the gross-up bullet below). → `DECISIONS.md`
- **The agency gross-up is a rep-only, order-wide ×1.15 multiplier on CPM and Cost — never impressions, never anything the model touches** (FLOW_REWORK_PLAN.md Phase 4b, replacing the old `agency_involved` toggle that lived in Section A and was set by drafting). "Apply agency gross-up (×1.15)" sits immediately above the editable plan grid (moved there from "near Generate" — it's the control that changes what a rep types into that grid's CPM/Cost cells, so it belongs beside them) as `agency_gross_up`; `markup = 1.15 if agency_gross_up else 1.0` is derived once, early, and applied in exactly one place, `compute_plan_totals` (via `row_markup`, so the broadcast exemption below still applies). `cost_from_impressions`/`impressions_from_cost`/`recompute_row`/`merge_plan_rows` carry no markup parameter at all any more — a row's stored Cost/CPM are always net. **The editable grid never shows a grossed number — it's net by definition — but the deck-preview table right below it (`preview_display`, built from `compute_plan_totals`'s own `preview_rows`, the same source the deck's own table reads) carries a CPM column that does**, so the toggle's effect is visible somewhere before Generate instead of only inside the generated file. **A number gets grossed exactly once, by the checkbox**: the drafting prompt tells the model to transcribe whatever rate the notes state, verbatim, even when the notes say to gross it up ("the net CPM is $32, gross it up" → the model writes 32, the rep ticks the box, the whole order becomes $36.80) — the settled business rule is that gross-up is always **order-wide**, never per-line, so there is no per-row exemption to build. The avails-PDF importer no longer auto-ticks the checkbox from a document's Agency field either; it surfaces the agency name as an `unresolved_internal` note instead. **Migration for a pre-Phase-4b proposal:** `rehydrate_proposal_into_form` detects one by the *absence* of the new `form_json["agency_gross_up"]` key, and when the legacy `form_json["markup"]` was 1.15, divides every restored non-broadcast, non-flat-fee row's Cost by 1.15 once (impressions are untouched — they were already net either way) and ticks the checkbox, so an old gross proposal doesn't get grossed a second time the instant the box renders. Guard: `tests/test_draft_regression.py`'s standing check that impressions are identical with the gross-up applied and not applied. **`total_budget_basis` ("net"/"gross", `_drafted_budget_basis`) is the same fix `avails_basis` already is, applied to a stated campaign budget**: only an explicit "gross" label converts anything (Python divides by `AGENCY_MARKUP` once, before the waterfall — the genuinely ambiguous case, commission mentioned with no stated side, stays net) and, unlike a bare `unresolved_internal` flag, `apply_draft_to_form` also ticks the checkbox itself — leaving it off after a confirmed gross conversion would show the rep a number nobody asked for. Still the model transcribing a label, never grossing anything itself. Guard: `tests/test_draft_regression.py`'s `check_gross_budget_basis`, `tests/test_draft_live.py`'s phrasing-variant check. → `DECISIONS.md`
- **A media-plan row can be Rate or Flat Fee, and a flat fee is not scaled by month count.** That requirement exposed a real bug: the full-flight total used to be `monthly_total * n_months`, which silently over-counted anything that doesn't scale linearly. Totals now accumulate each row's own full-flight cost and impressions. → `DECISIONS.md`
- **A Monthly-breakout option's Full Flight Total is computed live from `n_months`, never stored per row — editing the setup band's flight after a Monthly-breakout row is priced moves the quoted total with no row ever "rewritten," so no ordinary dirty-row protection catches it.** (A Full-Flight-breakout row's stored Cost IS the full-flight figure directly — immune by construction.) The setup band's flight-change guard warns (naming both dollar totals), blocks Generate, and requires a dismiss click; it does **not** freeze the old total while waiting — see `DECISIONS.md` for why freezing was proposed and rejected. Guard: `tests/test_flight_change_guard.py`. → `DECISIONS.md`
- **Audiences are vertical-independent, and a vertical prioritizes rather than filters.** The avails table and Audience finder are keyed off their own toggle, never off a selected vertical; `prioritize_catalog` sorts, it doesn't remove, and with no hint at all `build_catalog_slice` sends the **full** catalog rather than an arbitrary top-150 cut. → `DECISIONS.md`
- **One custom (non-RFP-selectable) audience per campaign, enforced but never silently.** Checked against the avails table itself whatever the source, with a visible `st.warning` rather than a silent drop. **The draft path caps structurally instead**: `apply_draft_to_form` keeps the first custom segment and moves the rest into `unresolved` as named alternatives, because a prompt instruction is a probability, not a guarantee. Guard: `custom_audience_cap`. → `DECISIONS.md`
- **A $0 media plan row is always wrong** — `resolve_drafted_lines` drops any line resolving to $0 with a note, and the prompt says no-charge items are Included-with-Campaign entries rather than plan lines. A freshly *seeded* rate row is $0 by design; it's fee rows that must never be zero. The one exemption is a `percent_of_avails` line with blank avails, where dropping it would discard the audience. → `DECISIONS.md`
- **% of avails (share of voice) is per LINE, never a deck-wide aggregate.** `show_sov` (default off) gates `_sov_suffix`, which appends `" (X% of avails)"` to a plan line's own impressions — both in the app's preview and in the slide-fill payload's per-row `impressions` field — only when that line has a real match. `matched_avails_for_row` resolves the match through `_group_ids`/`group_ids_of`, the same join merge/split/the map legend already use, never a text match on Targeting/Geo: zero matching ids (a drafted line, a quick-add line, a hand-typed line, a stale id whose group was deleted) is unmatched and shows nothing; two or more ids (a line built by `merge_plan_rows` combining several avails-backed lines into one) sums every id that still resolves, the same combining merge already does for that line's own Impressions and Cost — a line merged from Denver + Atlanta reports its percentage against their combined avails, not against neither market alone or a deck-wide total. `compute_plan_totals` takes an optional `groups_by_id` and stamps each `preview_row` with `matched_avails_monthly`/`matched_avails_full_flight` (the latter scaled by that row's own `row_months`, so a broadcast or merged line's full-flight percentage divides by the flight length that line actually runs in) so the app's preview and the slide read the same number. Blank whenever there's no real, non-zero avails to divide into — never a fabricated 0%/∞%, and never a guess at an unmatched line's avails. Guard: `tests/test_share_of_voice.py`.
- **An avails-PDF import's figures freeze to the DOCUMENT's own dates at import, never the plan's — a rep adjusts explicitly, or not at all.** (FLOW_REWORK_PLAN.md Phase 2, reversing this app's own earlier auto-proration.) `avails_monthly`/`avails_full_flight` are set once, from `avails_daily_rate`/`avails_monthly_from_daily_rate` run with the document's OWN flight on both sides — `avails_full_flight` is the document's stated total verbatim, never round-tripped through rate math. `avails_doc_start`/`avails_doc_end` (ISO strings) and `avails_doc_monthly`/`avails_doc_full_flight` (the frozen figures under their own names) ride alongside so a later adjustment is always reversible. `avails_flight_divergence` names a real mismatch between the plan's active per-month ranges and the document's own — derived by clipping the document's window to each calendar month the SAME way `flight_month_ranges` clips the plan's own, **not** by storing the avails-PDF parser's per-row `AvailsPeriod` list on the group: that was tried, and a raw list-of-dicts value nested inside a `targeting_groups` entry (itself a list of dicts) was found, live against the real 12-group Hershey document, to break Streamlit's own widget-identity bookkeeping on a later rerun — reproducible with no divergence UI, no D2 "Avail dates" column and no plan action involved at all, so this is a storage-shape hazard, not a bug in any of this feature's own code. The derivation is lossless for every document on hand (a real document's periods are always exactly calendar-month-clipped). `apply_pending_avails_plan_adjust` is the reversible, rep-triggered "Adjust to plan dates" / "Use document figure" action, queued the same way every other D2 mutation is; adjusting re-derives from the FROZEN doc figures (never a live, possibly-already-adjusted one, which would compound) reapplied across the plan's own active days (`flight_active_days`, skip-aware). Dates show in the D2 grid (a disabled "Avail dates" column, like "Detached") but never in the generated deck — a second flight competing with the plan's own would raise a question whose answer is internal bookkeeping. Guard: `tests/test_avails_import_proration.py`. → `DECISIONS.md`
- **Co-viewing is an explicit allowlist and a settings record, never a guessed line or a hardcoded number.** `is_coviewing_eligible_row` matches Premion Streaming TV and Live Sports lines ONLY (`COVIEWING_ELIGIBLE_TACTIC_PREFIXES`) — `line_type`/`targeting_copy` can't tell CTV apart from Streaming Retargeting or a sports package, since both carry the same values a retargeting line does. `show_coviewing` (default off) threads a multiplier from `app_settings` (key `coviewing`; `db.fetch_setting`/`load_coviewing_settings`, same cached/fallback shape as the rate card, `FALLBACK_COVIEWING` when Supabase is unreachable) into `compute_plan_totals`, which stamps each eligible line's `coviewing_additional_monthly` — `None`, never 0, for anything ineligible or a flat fee. Shown per line ("+N") in the app preview and on the slide's own `MONTHLY COVIEWING` column (`assembly.add_coviewing_column`, cloned the same way `add_cpm_column` clones Cost, called first so Coviewing lands left of CPM when both are on) — **deliberately no adjusted-CPM column**; the effective CPM (`effective_cpm_with_coviewing`, boosting only eligible lines' impressions before blending) is folded into a short citation instead. That citation lands on the plan slide's EXISTING "Terms & Conditions" text box as a fourth small-print paragraph (`assembly.add_coviewing_footnote`), not a new shape — measured against the real master deck, that box already sits within ~0.2in of the slide's bottom edge, which is exactly why the on-slide text is a condensed multiplier+source+CPM clause rather than the settings record's fuller `footnote` (shown instead in the app, next to the checkbox, where space isn't a constraint). `add_full_flight_total_row` counts optional columns (CPM, Coviewing, either, both, or neither) explicitly from the caller now rather than guessing from cell count, since a single `len(cells) >= 7` threshold could no longer tell them apart once a second optional column existed. Guard: `tests/test_coviewing.py`, including a real-render check that a doubled "Co-viewing:" label (the settings string and the footnote's own bold run both supplying the prefix) was caught only by looking at the rendered slide, not by any string-presence assertion.

### Broadcast and Wide Orbit

- **Broadcast lines are always gross and never marked up — settled, not a default.** A Wide Orbit cost already contains the agency commission, so `BROADCAST_EXCLUDED_FROM_AGENCY_MARKUP` holds the row at markup 1.0 **regardless of the agency gross-up checkbox**, enforced in `row_markup` — the **only** exemption from the order-wide multiplier, structural, never per-line. Recognition is by the **full** tactic suffix (`BROADCAST_TACTIC_MARKER`), deliberately not the shorter `"Broadcast Schedule"`, which is the rate-card product's own label. Renaming the tactic forfeits the exemption, which is what the grid caption warns about. → `DECISIONS.md`
- **An imported schedule replaces the rate-card broadcast line rather than joining it**, and station → market is a lookup, never a guess (`WUSA`→DC, `WPMT`/`FOX43`→Harrisburg; anything else is reported so the seller sets the geo by hand). Impressions and cost come from the WO summary and the **CPM is derived** from them, since the export's own CPM is rounded to cents. → `DECISIONS.md`
- **Wide Orbit schedules parse into one shape, and the units are the trap.** `wideorbit.parse_schedule` reads all three export formats into `Schedule(rows, summary)`. Impressions arrive **in thousands in the Planner exports and raw in the Campaign Schedule Report**, so `normalize_impressions` decides by reconciling against `cost / cpm * 1000` rather than trusting a per-format rule — guessing wrong is a 1000x error in a client-facing plan. Parse failures raise `ScheduleParseError` with a message aimed at a seller. **The test fixtures are real client schedules and are gitignored**; `tests/test_wideorbit.py` reports SKIP without them. → `DECISIONS.md`
- **The schedule's summary block is anchored to the table, not to the template.** `place_summary_below_table` runs after `condense_media_plan_table` and puts it at the table's real bottom plus clearance, clamped so it can't leave the slide; the shape must be captured **before** `fill_bullet_list_in_slide` consumes the token that finds it. Continuation pages have no summary. → `DECISIONS.md`

### Layout, fitting and text measurement

- **Slide content is fitted to the slide, not assumed to fit.** The media plan table's floor is **derived from the slide** (the topmost shape below the table that overlaps it horizontally), never looked up by shape name; font size is derived *from* the final row height, since PowerPoint grows a row whose text doesn't fit; Campaign Specs is measured and scaled to a 60% floor and then warns. Past the point where every row is at the minimum readable height, the table genuinely can't fit and that **warns** rather than shipping an overlap. When testing this, **locate the plan slide by its table** — two slides contain "Included with Campaign". → `DECISIONS.md`
- **The Campaign Specs client name is a width problem, not a height one.** Its box is `wrap="none"` + `spAutoFit`, so a long name draws straight out of the panel. `fit_no_wrap_title` shrinks on one line first (byte-identical to the old single-line behaviour, asserted on shape geometry), and only a name that would otherwise sit at the floor reaches phase 2, which wraps and re-walks the ladder. **The wrapped block grows upward from a fixed bottom**, anchored to where the *template's own* 42pt line ends. Guard: `check_client_name_fit`, which asserts both what the sizer decided and, over COM, what got drawn. → `DECISIONS.md`
- **Text is measured, not estimated, and the font it's measured in has to be the font it's drawn in.** `text_metrics.py` wraps against real glyph advances. Six things are load-bearing and each was a real defect: fonts are **discovered, not listed**; measure at a large reference size and scale down (PIL quantizes to whole pixels); the horizontal inset is not the vertical one; rows are sized **individually**, including headers and rows added after sizing; **a slide resolves its fonts against its OWN master, and this deck has 21** (`prs.slide_masters[0]` is the only one whose minor font is Calibri); and **nothing substitutes silently** — every resolution is recorded `exact`/`substituted`/`unavailable` and surfaced via `measurement_note()`. Guard: `tests/test_font_resolution.py` (offline, machine-independent). **Two settled decisions live with it — font bundling (declined) and `min_table_row_height()` vs PowerPoint's ~0.3in floor (won't fix); don't reopen either without new evidence.** → `DECISIONS.md`
- **A substituted face is measured through a per-face ratio table, not one global constant.** `assembly._SUBSTITUTE_WIDTH_RATIOS` is consulted whenever `resolve_font` reports anything but `exact`; an unmeasured face gets the worst ratio observed on any face, derived as `max()` of the table rather than typed in. Three paths need three different corrections (measured in the face / measured in Calibri / no font files at all), and a run whose family is present but whose bold cut is missing gets 1.0 and is not reported. Guards: `check_width_calibration` (offline), `check_client_name_fit` (COM). **Don't re-litigate extracting the embedded fonts** — they are EOT `TTCOMPRESSED` and PIL cannot open them. → `DECISIONS.md`
- **A cramped plan buys its type back from the slide, not from the reader.** Two font floors, and conflating them is what left long plans at 6pt: `_MIN_TABLE_FONT_PT` (6) is the absolute floor; `_COMFORTABLE_TABLE_FONT_PT` (9) is the signal to spend layout elsewhere. The threshold is a **font size, never a row count**. What it spends is the "Included with Campaign" band — but the plan slide is a **signable document**, so the band may be made smaller and moved and may **never leave the page the signature is on**. Sizing runs twice (carry `template_metrics` across both passes), the band is parked low during compression and floated back afterwards, and the decision is **per deck, not per slide**. → `DECISIONS.md`
- **Reserving generously and refusing generously are different things.** `_row_height_for` keeps a 0.1in per-row cushion because PowerPoint draws these rows taller than their content accounts for; the "cannot fit" warning is judged on `_row_text_height` (bare lines, no cushion), because judging it on reserved height declared a 12-line plan too tall for a slide PowerPoint then drew with room to spare. → `DECISIONS.md`
- **Validate layout against the renderer, and read PowerPoint's row heights correctly.** PowerPoint reports a row's height as **max(declared, needed)**, so a row reported *at* its declared height says nothing — the real signal is a row reported **taller** than declared, meaning the text didn't fit and PowerPoint grew it. Pair tables by **signature** (slide, shape, first row), never by index, and scope the check to tables the sizer manages. `tests/validate_text_metrics.py`. → `DECISIONS.md`

### Drafting, the catalog and the Claude API

- **The AI draft path does no arithmetic — Claude returns intent, Python does the math.** Claude returns `media_plan_lines`, one entry per intended **row**; each line's `allocation` is exactly one of `flat_amount`, `percent_of_total`, `percent_of_remainder`, `split_evenly` or `percent_of_avails`, resolved as a waterfall (avails and fixed amounts first, then remainder, then even split) before impressions are computed from the same `PRODUCTS` CPM table the rest of the app uses. A line can name `custom_fee` for a one-time fee, or `sport:<key>` for a package. Segments Claude names are validated against the real catalog and dropped with a note if unmatched, never silently kept. → `DECISIONS.md`
- **A drafted plan is authoritative over Section C.** The draft clears every product toggle before switching on only the ones its lines use, and the prompt states outright that there is no mandatory line and no default product. Sports selection is the union of the `sports` array and any `sport:` lines. → `DECISIONS.md`
- **The seed key is built by `read_seed_selections` and nowhere else.** A hand-rolled copy that merely omits a key makes `main()` take its "product selections changed" branch and reseed every option's rows to $0 while leaving the option *names* alone — which presents as "the budget allocation is broken" and is near-undiagnosable. `read_products_selection(get=None)`/`read_seed_selections(get=None)` take an optional getter so there is one construction. **Never rebuild that dict at a call site**; adding a product widget to `read_products_selection` is the whole change. → `DECISIONS.md`
- **A drafted line may carry its own `cpm`, and an override always announces itself** in `unresolved`, because nothing downstream distinguishes a negotiated rate from a standard one. Omit the field to take the rate card default; a non-numeric or ≤ 0 value falls back rather than pricing at zero; a `cpm` on a `custom_fee` line is ignored and flagged. `unresolved` is deduped on the way out. → `DECISIONS.md`
- **A drafted budget is always a campaign total; the breakout is a separate, presentational question.** `resolve_drafted_lines` works in full-flight amounts and `spread_rows_over_months` divides rate rows across the flight (deliberately unrounded, so month × count still ties to the quoted budget). Flat fees are never divided. **Every option must carry its own `total_budget`**, and an option that can't be priced is named in the error rather than reported as "no usable lines". → `DECISIONS.md`
- **A re-draft is merged over the previous draft**, because a dropped field isn't neutral — the incident that settled this: a re-draft once dropped the (now-retired) `agency_involved` field, and a missing boolean read as false rather than "unchanged," quietly repricing every line at net. `call_claude_redraft` returns `{**previous, **revised}`. One clarification round only (`draft_round`), with hand edits protected at section granularity via `DRAFT_KEY_SECTIONS`, and preserved sections named back to the user. → `DECISIONS.md`
- **Avails are ingested when the notes supply them, invented never, and always stored monthly.** `audiences[].max_avails`/`avails_basis` are populated only from a figure the notes state — never estimated, carried across, or worked back from a budget. The D2 toggle changes what is *shown* (and the slide's column header, which is literal text rewritten run-by-run); `restore_untouched_avails` keeps an unedited row byte-for-byte so flipping the basis can't walk a stored number. Reach is invariant to the basis. Guard: `tests/test_avails_reach.py`. → `DECISIONS.md`
- **The drafting prompt states rules positively — a rule that quotes what it forbids can teach the exact output it is trying to prevent.** A live run echoed the very identifier the prohibition quoted. Say what to write, not what not to write; where a field name must stay in context, put the plain-language substitute at the point where the field is explained. → `DECISIONS.md`
- **A failed Claude call has to say which failure it was — to the log, not to the rep.** `stop_reason` is read **before** the JSON is parsed (a truncated response is not a formatting problem), text is joined from every block, `ANTHROPIC_MAX_TOKENS` is **16000** — sized against the biggest realistic draft and the practical ceiling for a non-streaming call — and every call is logged (label, stop reason, tokens, request id, first/last 200 chars) to the console and to `%TEMP%/proposal_builder_claude_calls.log`. **A preamble instead of raw JSON is salvaged, not prevented**: `_extract_largest_json_object` scans every balanced `{...}` in the response and takes the **largest**, not the first — the first was tried and shipped, and it silently corrupted a real draft the very next day, because a preamble routinely quotes a small schema fragment verbatim while reasoning (`{"mode": "all"}`) and that fragment is itself complete, valid JSON. An assistant-turn prefill was tried as the structural fix and is a dead end on this model — `claude-sonnet-4-6` 400s on it ("does not support assistant message prefill") — don't re-attempt it without re-checking that against the model in force. Empty, truncated and unparseable responses retry once, appending a corrective instruction to the prompt rather than resending an identical one; a refusal does not retry. **Every message a rep actually sees is plain language — what happened, then retry, then "Report an issue" — with no file paths, session keys, or function/constant names.** The real diagnostic detail (stop_reason, first 200 chars) goes into `st.session_state["last_claude_failure"]` instead, scoped to the single most recent failure and cleared on the next success, which `capture_feedback_state` folds into a rep's own bug report. Guard: `tests/test_claude_call.py`. → `DECISIONS.md`
- **Vertical detection matches whole words over one combined table, longest phrase first.** `VERTICAL_HINT_SYNONYMS` carries ~136 trade names; matching is **word-boundary regex, not substring** ("auto" in "automatic", "spa" in "Spanish"), and trade names and vertical names live in **one** table so "credit union promoting auto loans" doesn't resolve to `auto`. Terms describing what's advertised rather than who's advertising don't belong here. Guard: `test_vertical_hints.py`. → `DECISIONS.md`
- **Dynamic Video Ads are a flat fee.** The Section C toggle includes the slide and seeds a flat-fee row; the product sits in `PRODUCT_TO_WIDGET_KEYS` and `ATTRIBUTION_FIELD_MAP` but is excluded from the line namespace via `NON_LINE_PRODUCT_KEYS`, or a drafted line could name it, find no CPM and produce a $0 row. → `DECISIONS.md`

### Case studies

- **A case study goes into a deck as images when it has them, and as copied slides when it doesn't.** `append_case_studies` takes either shape and `app.case_study_source` resolves both, so generate and rebuild can't disagree. Images exist because cross-deck OOXML copying produced five distinct corruption bugs and still can't reproduce PowerPoint's live autofit; they are also **smaller**. The permanent cost is that an image slide isn't selectable or editable text, which is why the copy path stays. → `DECISIONS.md`
- **Cross-deck copying is much harder than in-deck duplication.** `copy_slide_into` imports every referenced part and renumbers it: **never `get_or_add_image_part`** (it re-encodes and fails on EMF/SVG), **a chart is not a leaf** (it carries a workbook plus colour and style parts, and rIds inside copied XML need rewriting), and **slide backgrounds live on `<p:cSld>`**, outside the shape tree. One `ImportCache` must span a run of copies. → `DECISIONS.md`
- **A copied case study slide inherits nothing, because it is flattened on arrival.** `slide_inheritance.flatten_inherited_formatting` resolves placeholder geometry, body/run/paragraph properties, then scheme colours and theme fonts **last**, strips `<p:ph>`, adds explicit `prstGeom` (a de-placeholdered `<p:sp>` *or* `<p:pic>` has no geometry and draws nothing), and copies the layout's and master's own shapes behind the slide with `showMasterSp="0"`. **The faithful alternative — importing the source layout/master/theme — was built and abandoned**; don't retry it without new information. One residual is reported rather than hidden, counted by `tests/test_case_study_import.py`. → `DECISIONS.md`
- **Case study images are generated locally, never by the app.** `render_case_study_images.py --pending|--all|--list` renders over PowerPoint COM and uploads to the `case_studies` bucket; Streamlit Cloud has neither PowerPoint nor Proxima Nova, so rendering there would store images that aren't what the case study looks like. Empty `slide_images` *is* the pending queue. `render_pending.bat` and `schedule_render_pending.ps1 -Register` run it hands-off; `--skip-if-busy` exists because a COM `Dispatch` **attaches to a running instance**. → `DECISIONS.md`
- **Never key a cache on `id()` when the objects can be collected.** `copy_slide_into` opens its source `Presentation` locally, so its parts are garbage the moment the call returns and CPython reuses the addresses — a style part landed on a freed workbook's address and the cache handed back the workbook. Keyed on `(id(part.package), partname)`, with the source presentations retained. Deduplication is limited to `/ppt/media/`: two charts sharing one embedded workbook is a file PowerPoint refuses. **Both failures were invisible to every structural check** — which is why a failure to open counts as a test failure, and why `package_check.check_package` runs on every deck the fast suite builds. → `DECISIONS.md`

### Slide vault

- **The case-study vault again, one slide at a time — a colleague uploads a `.pptx` and ticks the individual slides worth keeping, never pre-selected into a proposal.** One row is one picked slide, not one upload — several `slide_vault` rows share one `storage_path` (`slide_index` tells them apart), so a deck is never split apart the way extracting a single slide out on its own would require; that's exactly the cross-deck copy problem the case-study vault's five corruption bugs came from. Verticals/products/a free-text `purpose` tag it; `db.slide_vault_render_path` (`"image"`/`"copy"`) is the image-vs-copy signal, `slide_image` singular where `case_studies.slide_images` is an array, null meaning not-yet-rendered — the pending queue, same convention. `render_slide_vault_images.py` groups pending rows by `storage_path` so a source deck is opened through PowerPoint COM once regardless of how many slides were picked from it.
- **Placement is per slide, resolved fresh after every graft, never cached across one.** `assembly.vault_slide_insert_index(prs, placement)` derives `"front"` (index 1, after the cover), `"before_plan"` (the same `case_study_insert_index` call case studies use, so a vault slide grafted after them lands after them too, not interleaved or ahead) and `"appendix"` (current end of deck) by scanning the deck AS IT STANDS. `append_vault_slides` groups selected slides by placement and re-derives each group's anchor immediately before grafting that group — computing all three up front, before any group is inserted, is the exact bug `tests/test_slide_vault.py`'s combined-order check exists to catch (a stale position lands a `"before_plan"` slide in the middle of the case-study block instead of after it). ## Git workflow — dev/main split (2026-09-23)

- **All work commits to `dev` and pushes to `origin/dev`. `main` only changes through the merge routine below — never a direct commit, never a direct push.** `dev` exists so daytime work never touches the public app (`main`'s own Streamlit Cloud deployment) until it's deliberately promoted. Check out `dev` at the start of a session; if a session somehow finds itself on `main` mid-task, switch to `dev` before committing anything, don't commit to `main` and sort it out later.
- **`DEV_MODE` (`app.dev_mode_active()`) shows a persistent, impossible-to-miss banner at the top of every page, including the login screen** — read from the OS environment (a local process) or `st.secrets` (the deployed dev instance; unlike `PROPOSAL_BUILDER_TEST_MODE` this one is *meant* to run on Streamlit Cloud, since the whole point is a second, separately-deployed app). Off (unset) means byte-for-byte today's behavior — the public app never shows this banner and never reads the flag as true by accident. Guard: `tests/test_dev_mode.py`.
- **`DECK_CHANNEL` (`db.deck_channel()`) decides which row a `deck_versions`/`report_deck_versions`/`audience_usage_versions` fetch uses.** `"active"` (the default, and the only mode the public app ever runs in) is today's behavior unchanged — the single row with `active=true`. `"latest"` (the dev app) instead takes the most recently **uploaded** row regardless of its active flag, so a freshly uploaded master deck, report template or audience-usage workbook can be previewed on the dev deployment before anyone commits to it for real. One shared helper, `db._fetch_version_row`, backs all three lookups — the channel logic lives in exactly one place, not three copies that could drift. Guard: `tests/test_dev_mode.py`.
- **Uploading a new deck/template/workbook version is a dev-time action; activating it is a merge-time action, and only the merge routine below does it.** Never call an `activate_*` function from a session working on `dev` — a rep-facing template or ratecard change reaches the public app only through "nightly merge," never by being uploaded. DDL stages stay exactly as documented elsewhere in this file (additive, idempotent, pasted into Supabase by hand ahead of the code) — this split doesn't change that, only when a version goes live.

### The merge routine — triggered by the user saying "nightly merge" or "merge dev to main"

When triggered, do exactly this, **stop at the first failure, and never ask a question in between** — the routine either completes cleanly or leaves `main` exactly as it was:

1. Confirm `dev` is clean (`git status`) and pushed. If the chunked full sweep (`python tests/run_all.py`, all 8 chunks) hasn't run since `dev`'s last commit, run it now; if it's red, **stop** — nothing below runs.
2. `git checkout main && git pull && git merge dev --ff-only`. If it can't fast-forward, **stop** — don't resolve unattended; that's a human decision.
3. `git push origin main` (the user runs this step themselves, same as any push — see "the sandboxed shell can't do this" above).
4. Activate any deck/report/workbook version uploaded this cycle and not yet active. Print which version(s) went live.
5. Wait for the public app to rebuild, then confirm the sidebar build stamp on the **public** URL matches the merge commit. Say so plainly if it doesn't land within a few minutes.
6. `git checkout dev`. Report in three lines: the commit range merged, what was activated, the public build stamp.

If anything in steps 1–5 fails, `main` stays exactly as it was before the routine started — no partial merges, no manual patch-ups.

- **Radius mode takes many centers, not one.** The geo-definition expander's Radius mode is a textarea, one center (zip or address) per line, at a shared default radius; a line ending `", <number>"` overrides the radius for that line alone (`app.parse_radius_centers`), recognized only when the text after the *last* comma parses as a plain number. Each center resolves through its own `geo_resolver.radius_to_zips` call, which is what makes a per-center report possible (a summary line plus one line per center naming its zip count or that it couldn't be geocoded) and lets the union dedupe overlapping circles by construction. `geo_def["centers"]` stays backward compatible — an un-overridden center is still a bare string. Guard: `tests/test_group_geo_resolution.py`.

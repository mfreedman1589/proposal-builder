# Premion Proposal Builder

A Streamlit app that assembles polished, client-personalized Premion CTV/OTT proposal decks from a form, by deleting unselected slides from a master `.pptx` and filling the retained template slides. Phase 1 (current): form + assembly engine + local download; Supabase not built yet, but the Claude API is now wired in for two features -- drafting a first pass at the form from pasted meeting notes, and an audience-segment finder/recommender.

**Stack:** Streamlit (form + UI), python-pptx (deck assembly/fill), pdfplumber (audience catalog PDF parsing), Anthropic Claude API (`claude-sonnet-4-6` -- draft-from-notes + audience suggestions), Supabase (planned, not built).

**Source of truth:** `proposal_builder_build_spec.md` is the full spec (data model, form fields, slide map, phasing). Read it before making non-trivial changes. `master_v1_1_changelog.md` documents the current master deck version's token conventions and what changed from v1.

## Key conventions

- **Token fill convention:** template slides carry `{{TOKEN}}` placeholders in run text. Fill by finding the run containing the token and doing `run.text = run.text.replace(placeholder, value)`. **Never assign `text_frame.text`** — it collapses all run-level formatting (font, color, size) on that paragraph. Multi-item content (bullet lists, table rows) is filled by deep-copying the tokenized paragraph/row XML element and inserting clones as siblings, then filling each clone the same way. See `fill_bullet_list` / `fill_table_rows` in `assembly.py`.
- **Slide map is always derived by scanning, never hardcoded.** `slide_map.py` opens the master deck and classifies every slide into a `condition_key` (e.g. `vertical:healthcare`, `vertical:healthcare:targeting`, `sport:nfl_playoffs`, `sport_viewership:nfl_playoffs`, `full_deck`, `transitional_divider`) by matching text anchors, with a small carry-forward default for undifferentiated divider slides. If the master deck is replaced with a new version, do **not** hand-patch slide numbers — update the anchor rules in `slide_map.py` if a new slide type needs one, then let it re-scan. This was a direct, hard-learned lesson from the v1 → v1.1 deck migration (slide count and positions shifted; a stale hardcoded map would have silently mis-assembled decks). Watch for anchor collisions with boilerplate footer text (e.g. "CONF" matching "confidential") — needles should be as specific as the real text allows.
- Slide deletion works by removing the `<p:sldId>` from `presentation.xml`'s `sldIdLst` and dropping the corresponding relationship (`prs.part.drop_rel`) — python-pptx then automatically omits any part unreachable from the package's relationship graph on save, so orphaned slide parts clean themselves up. Reordering (e.g. moving the vertical stats slide to position 3) is the same idea: remove the `<p:sldId>` and `.insert()` it back at the target index.
- The **"Standard" preset is a literal slide-number allowlist** (`STANDARD_CORE_SLIDES` in `assembly.py`), unioned in on top of whatever condition_keys resolve — it can force in a slide (e.g. slide 13, the avails template) even when the toggle-driven logic alone wouldn't have added it. Because of that, targeting/avails mutual exclusion is enforced as a **post-processing step in `build_presentation`** based on which slides actually ended up in `keep_numbers` (not on the toggle value alone) — this applies globally across all three presets: whenever the personalized avails template is present, the vertical's static Precision Targeting slide is dropped, full stop. (An earlier version of this note said the two slides could appear together under "Standard" — that was a real bug, fixed; don't reintroduce it by going back to toggle-only exclusion.)
- `.pptx` and `.pdf` files are gitignored (master deck, generated test output, source brochure) — never commit them. Secrets live in `.streamlit/secrets.toml` (gitignored) — `APP_PASSWORD` (shared-password gate) and `ANTHROPIC_API_KEY` (draft-from-notes + audience suggest, read via `st.secrets.get("ANTHROPIC_API_KEY")` at runtime). That file is fenced off hard: `.claude/settings.json` denies reading it via any tool, and the sandbox itself blocks even a blind existence/append check on it from this assistant — the user edits it directly.
- **Audience catalog is scanned from the brochure PDF, never hand-transcribed.** `audience_catalog.py`'s `load_audience_catalog()` (cached with `@st.cache_data`) parses `PREMION_Audience Targeting (1).pdf` — segment name, category, subcategory, and Salesforce RFP-selectable status (detected via the light-cyan highlight rectangle behind each RFP-selectable line, a fill shape, not a text-color property) — then merges in `times_used` from `audience_segments_derived.csv` (that CSV's own `category`/`is_custom` columns are not used; the PDF is the authority on those). If the brochure is ever replaced, re-verify against page 2's own condensed "accessible in Salesforce RFP" roster the same way this was validated (104/105 exact agreement on first build; the one mismatch was a genuine "Parent"/"Parents" typo already in the source PDF) — don't assume a new PDF's layout quirks match. Two non-obvious PDF-geometry gotchas if the parser ever needs revisiting: (1) a subcategory's segment list snakes across the page's column bands without repeating its header in later columns, so the running "current subcategory" must be tracked *per category code*, not per column or as one single value — different categories' sections interleave in raw column-then-top reading order; (2) some categories spell their subcategory headers out in full ("FINANCE", "HEALTH", "ENTERTAINMENT") while segment rows use the abbreviated code ("FIN", "HLTH", "ENT") — `HEADER_CATEGORY_ALIASES` bridges the two.
- **The AI draft path does no arithmetic — Claude returns intent, Python does the math.** `app.py`'s "Draft from notes" panel and "Audience finder" → Suggest mode both call Claude (`claude-sonnet-4-6`, JSON-only response contract, markdown-fence-stripped and retried once on parse failure). The draft prompt includes today's date and an explicit "resolve a year-less date to the next upcoming occurrence, never the past" rule (flagged in `unresolved` either way) — without it, the model would default a bare "September through November" to whatever year it last trained on, not the real current one. The two prompts also share one `AUDIENCE_MATCH_GUIDANCE` string telling the model to prefer a specific matching segment (e.g. a FIN segment for "in-market for deposit accounts") over a generic demographic proxy (e.g. a DEMO homeowner/income segment) — both send the model the *same* vertical-relevant catalog slice already (verified: all 22 FIN segments are present in a banking-vertical slice), so a mismatch between the two paths' picks was a prompt-emphasis gap, not a missing-data one.

  For drafting, Claude returns the whole media plan as `media_plan_lines` — one entry per intended **row**, not one per product (the same product can appear on multiple lines with different `label`/`audience_track`, e.g. a Commercial vs. Retail split, each becoming its own row with the label appended to the tactic name). Each line's `allocation` is exactly one of `flat_amount`, `percent_of_total`, `percent_of_remainder`, or `split_evenly`; `apply_draft_to_form()` resolves them as a waterfall — flat amounts and percent-of-total first, then percent-of-remainder out of what's left, then `split_evenly` divides whatever remains evenly across those lines — and only then computes impressions = amount ÷ (CPM × markup) × 1000, reusing the same `PRODUCTS` CPM table and cost formula the rest of the app already uses. A line can also use the special product value `custom_fee` for a one-time flat fee unrelated to any real media-buy product (e.g. a production/creative fee), using its `label` as the tactic name directly. Any audience segment Claude names (in the separate `audiences` array, for the avails table — distinct from a line's free-text `audience_track`) is checked against the real catalog via `validate_segments()` — unmatched names are dropped with a note in `unresolved`, never silently kept. Draft values are written into `st.session_state` keyed to each widget *before* that widget renders, followed by `st.rerun()` — Streamlit raises if you assign to a widget's value after it's already instantiated. Sections touched by the last draft show a small badge caption that clears via each widget's own `on_change` the moment the user edits anything in that section.
- **A media-plan row can be Rate (impressions × CPM) or Flat Fee — a UI-level distinction, not just a drafting one.** Any row's `Type` column can be set to "Flat Fee" (independent of whether it came from a draft): Impressions/CPM are ignored and the row's cost is its `Flat Cost` value directly — no markup, and **not** scaled by month count, since a one-time fee isn't a recurring rate. That "not scaled" requirement exposed a real pre-existing bug: the full-flight total used to be computed as `monthly_total_cost * n_months`, which is only correct if every row scales linearly with month count — a flat fee doesn't, so that shortcut would have silently over-counted it by the number of active months. Fixed by accumulating each row's own `full_flight_cost`/`full_flight_impressions` directly instead of deriving the totals from the monthly ones. `assembly.py` needed **no changes** for flat-fee rendering — its table fill is plain per-cell token-string replacement, so passing `"--"` for a flat-fee row's impressions renders exactly like any other string value would.
- **One custom (non-RFP-selectable) audience per campaign, enforced but never silently.** Checked directly against the D2 avails table itself (catches manual edits, "Audience finder" browse/suggest adds, and AI-drafted audiences alike, regardless of source) and, in Suggest mode, against a recommendation set specifically before any of it gets added — both show a visible `st.warning` rather than dropping anything on your behalf.
- **Streamlit dev server caveat:** `import assembly` / `import slide_map` are cached in the running process's `sys.modules`. Streamlit's file-watcher reloads and reruns `app.py` on save, but does **not** reload already-imported modules — editing `assembly.py`/`slide_map.py` while the server is running will silently keep executing the old code until the `streamlit run` process itself is restarted. Always restart the process (not just the browser tab) after editing those files, and treat a test that "should have changed but didn't" as a signal to check for this first.

## Running things

- **Assembly engine standalone:** `python assembly.py` — runs the hardcoded `SELECTIONS`/`FILL_DATA` at the bottom of the file against `TEGNA_MASTER_DECK_v1_1.pptx` and writes `test.pptx`.
- **Full app:** `streamlit run app.py`, then log in with the password in `.streamlit/secrets.toml`.
- Python and `streamlit`/`pandas`/`python-pptx`/`Pillow`/`pdfplumber`/`anthropic` are installed locally (there was no system Python before this project — installed via winget). `git push` needs an interactive login (Git Credential Manager) that the sandboxed shell can't do; the user runs it via `! git push` themselves.
- **Permissions:** `.claude/settings.json` (committed) allowlists routine commands so they don't prompt every time — git status/diff/log/add/commit/push/pull/branch/checkout, python/python3/py, `streamlit run`, pip install/list/show, read-only file inspection (ls/cat/head/tail/etc.), and Edit/Write within the project. It explicitly denies force-push and history-rewriting git commands, recursive deletes, and any read of `.streamlit/secrets.toml`. Personal one-off approvals go in `.claude/settings.local.json` instead (gitignored, not shared).

Verified against master deck v1.1 (118 slides).

Since then: three presentation presets (Quick Pitch / Standard [default, literal slide-number allowlist] / Extended); transitional section-divider slides (Premium Content/Precision Targeting/Attribution+Measurement) dropped from every preset; the selected vertical's industry-expertise stats slide is reordered to position 3; the vertical's static Precision Targeting slide and the personalized avails template are mutually exclusive **globally, across all presets** (post-processing step in `build_presentation`, not toggle-only — see note above); per-sport viewership slides (not the whole coarse block) shown per selected sport; media plan supports Monthly/Full Flight breakout with a calendar-driven active-months picker (custom/skipped months supported) and a "Duplicate line" button for per-line customization (e.g. same product, different audience); Streaming Retargeting and Live Sports lines get fixed default targeting copy, others default from the Campaign Specs Audience field; the media-plan table auto-condenses row height/font size when it would otherwise overlap the "Included with Campaign" graphic below it, and gains an extra "Full Flight Total" row when more than one month is active.

Media-plan rows also track a **per-row dirty flag** (`st.session_state["media_plan_dirty"]` in `app.py`): editing any cell marks that row dirty, and re-seeding from the shared Audience/Geography/Flight fields (`resolve_row_defaults`) only touches rows that are still clean. Rows added via the grid's own "+" or via "Duplicate line" start dirty. This was a deliberate fix — the original version re-seeded every row on any shared-field change, silently wiping manual edits.

Product/format granularity: Streaming Retargeting, and Audience Marketplace's Audience Targeting/Geofencing/Site Retargeting, each now split into separate Display and Pre-Roll checkboxes (`app.py` Section C), seeding their own media-plan line with the matching `PRODUCTS` entry and CPM. Live Sports CPMs come from `SPORT_CPM`, sourced from `PREMION_Live Sports Rates.xlsx` (Desktop, not in the repo) — falls back to `DEFAULT_SPORT_CPM` for any sport key not on that ratecard.

The master deck is now **119 slides** (was 118) — the user added a dedicated PGA Majors package slide at position 112, splitting what used to be one combined "Golf / PGA" sport option into two: `golf` (the pre-existing general Live Golf package + viewership slides) and `pga_majors` (new package slide + its own pre-existing-but-previously-unmapped "PGA Majors Viewers" slide). `slide_map.py`'s `_classify_sport_package`/`_classify_sport_viewership` were updated accordingly; rule order matters here too — the bare `"GOLF"` viewership rule must come *after* the `PGA` and `PRESTIGE` checks, since the Prestige Sports Viewers slide's own MRI footnote text contains "Streams Golf, Tennis, Horse Racing" and would otherwise misclassify it. Whenever the master deck changes again, re-run `python slide_map.py` and confirm zero `WARNING` output (100% resolution) before trusting anything downstream.

Ratecard audit (per user request): no other sport currently has the old golf/PGA pattern (two ratecard rows + two existing dedicated slides collapsed into one app option). Two ratecard rows have **no deck slide and no app option at all**: MLB Home Team Regular Season ($65, restricted to 14 teams) and NFL Regular Season – ABC MNF ($70) — plus Motorsports ($59), which has a viewership slide but no package slide. These aren't split-needed like golf/PGA was; they'd need a new master-deck slide added first (same as PGA Majors just got) before they could become selectable.

AI drafting and audience lookup, built in three commits: (1) `audience_catalog.py` — the scanned PDF catalog + CSV `times_used` merge + `validate_segments()`, described above; (2) a "Draft from notes" panel above Section A — paste meeting/discovery notes, Claude drafts client basics, vertical/market, flight dates, campaign-specs bullets, the media plan (as line-level budget intent, not arithmetic), audiences, attribution, and sports, all pre-filled into the form for review, with anything ambiguous surfaced in an `unresolved` list rather than guessed silently; (3) an "Audience finder" expander in Section D2 — Browse/search the catalog by category and name, or describe the client/campaign and let Claude suggest segments (exact catalog names, validated, each with a one-line rationale) — either way, "Add" appends a row to the avails table.

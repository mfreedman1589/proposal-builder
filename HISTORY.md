## Where the project lives

- **The project lives at `C:\projects\proposal-builder`, deliberately outside OneDrive.** It used to sit in `OneDrive - TEGNA\Documents\`, and sync was a recurring source of failures rather than an inconvenience: OneDrive held handles on directories it was mid-upload (so `rmtree` raised `PermissionError`), held a freshly written 25MB deck long enough that PowerPoint refused to open it, treated generated decks as co-authored and raised a **modal** conflict dialog that blocks every COM call until a human dismisses it, and restored a deleted build directory from the cloud afterwards. Nothing in the code ever referenced an absolute path, so the move was a re-clone plus copying the handful of gitignored files (secrets, master deck, `case_studies_source/`, the Wide Orbit fixtures, the audience catalog PDF). Renders go to `deck_render.render_root()` — under `%LOCALAPPDATA%\Temp` — which is outside sync wherever the project sits. Keep it that way: a path with no spaces and no sync agent is worth more here than tidiness.

## Build status and verification log

**Done:** git repo + GitHub remote; standalone assembly engine (`assembly.py`) with scan-based `slide_map.py`; personalization fill (client title, Campaign Specs bullets, targeting/avails table, media plan table, logo swap) all via the token convention; Streamlit form (`app.py`) covering spec sections A–E, wired to `assembly.py`, with smart defaults (vertical → healthcare/Arrivalist/Polk info, agency → gross markup, Live Sports → sports picker), password gate, and a working Generate → download flow. Verified against master deck v1.1 (118 slides).

Since then: three presentation presets (Quick Pitch / Standard [default, literal slide-number allowlist] / Extended); transitional section-divider slides (Premium Content/Precision Targeting/Attribution+Measurement) dropped from every preset; the selected vertical's industry-expertise stats slide is reordered to position 3; the vertical's static Precision Targeting slide and the personalized avails template are mutually exclusive **globally, across all presets** (post-processing step in `build_presentation`, not toggle-only — see note above); per-sport viewership slides (not the whole coarse block) shown per selected sport; media plan supports Monthly/Full Flight breakout with a calendar-driven active-months picker (custom/skipped months supported) and a "Duplicate line" button for per-line customization (e.g. same product, different audience); Streaming Retargeting and Live Sports lines get fixed default targeting copy, others default from the Campaign Specs Audience field; the media-plan table auto-condenses row height/font size when it would otherwise overlap the "Included with Campaign" graphic below it, and gains an extra "Full Flight Total" row when more than one month is active.

Media-plan rows also track a **per-row dirty flag** (each option's own `dirty` list in `app.py`): editing any cell marks that row dirty, and re-seeding from the shared Audience/Geography/Flight fields (`resolve_row_defaults`) only touches rows that are still clean. Rows added via the grid's own "+", via "Duplicate line", by cloning an option, or from an AI draft all start dirty. This was a deliberate fix — the original version re-seeded every row on any shared-field change, silently wiping manual edits. The same principle now extends to the whole form at section granularity for the clarify-and-re-draft round (see `DRAFT_KEY_SECTIONS` above).

Product/format granularity: Streaming Retargeting, and Audience Marketplace's Audience Targeting/Geofencing/Site Retargeting, each now split into separate Display and Pre-Roll checkboxes (`app.py` Section C), seeding their own media-plan line with the matching `PRODUCTS` entry and CPM. Live Sports CPMs come from `SPORT_CPM`, sourced from `PREMION_Live Sports Rates.xlsx` (Desktop, not in the repo) — falls back to `DEFAULT_SPORT_CPM` for any sport key not on that ratecard.

The master deck is now **119 slides** (was 118) — the user added a dedicated PGA Majors package slide at position 112, splitting what used to be one combined "Golf / PGA" sport option into two: `golf` (the pre-existing general Live Golf package + viewership slides) and `pga_majors` (new package slide + its own pre-existing-but-previously-unmapped "PGA Majors Viewers" slide). `slide_map.py`'s `_classify_sport_package`/`_classify_sport_viewership` were updated accordingly; rule order matters here too — the bare `"GOLF"` viewership rule must come *after* the `PGA` and `PRESTIGE` checks, since the Prestige Sports Viewers slide's own MRI footnote text contains "Streams Golf, Tennis, Horse Racing" and would otherwise misclassify it. Whenever the master deck changes again, re-run `python slide_map.py` and confirm zero `WARNING` output (100% resolution) before trusting anything downstream.

Ratecard audit (per user request): no other sport currently has the old golf/PGA pattern (two ratecard rows + two existing dedicated slides collapsed into one app option). Two ratecard rows have **no deck slide and no app option at all**: MLB Home Team Regular Season ($65, restricted to 14 teams) and NFL Regular Season – ABC MNF ($70) — plus Motorsports ($59), which has a viewership slide but no package slide. These aren't split-needed like golf/PGA was; they'd need a new master-deck slide added first (same as PGA Majors just got) before they could become selectable.

AI drafting and audience lookup, built in three commits: (1) `audience_catalog.py` — the scanned PDF catalog + CSV `times_used` merge + `validate_segments()`, described above; (2) a "Draft from notes" panel above Section A — paste meeting/discovery notes, Claude drafts client basics, vertical/market, flight dates, campaign-specs bullets, the media plan (as line-level budget intent, not arithmetic), audiences, attribution, and sports, all pre-filled into the form for review, with anything ambiguous surfaced in an `unresolved` list rather than guessed silently; (3) an "Audience finder" expander in Section D2 — Browse/search the catalog by category and name, or describe the client/campaign and let Claude suggest segments (exact catalog names, validated, each with a one-line rationale) — either way, "Add" appends a row to the avails table. Tested end-to-end against the live Anthropic API, not just unit-level: a $60K/agency/four-audiences/DC/Sep-Nov drafting scenario landed budget math within a penny of target, and an auto-dealership description returned 8 relevant, validated segment recommendations.

Follow-up fixes from live testing (see the line-level `media_plan_lines`/flat-fee/date-awareness note above): the draft schema's `budget_allocation` (one entry per product) was replaced with `media_plan_lines` (one entry per intended row, supporting `flat_amount`/`percent_of_total`/`percent_of_remainder`/`split_evenly` allocations resolved as a waterfall, plus a `custom_fee` product for one-time flat fees); the media plan itself gained a Rate/Flat Fee row `Type` (independent of drafting), which surfaced and fixed a real full-flight-total bug (it was computed as `monthly_total_cost * n_months`, silently over-counting anything that doesn't scale linearly with month count); and the draft prompt now carries today's date so year-less dates ("September through November") resolve to the next upcoming occurrence instead of a stale training-data year. Re-verified end-to-end: a four-line Blue Ridge Bank scenario (60/40 Premion split of the remainder, a flat retargeting amount, a flat production fee) landed at exactly the target total, and flight dates resolved to the correct upcoming year.

Second round of fixes from live testing, six commits (see the corresponding Key conventions notes above for the mechanics and the reasoning):

1. **Multiple plan options (1–3).** Media plan renders as one tab per option, each with its own name/lines/breakout/totals; a new option starts blank or clones an existing one. Generation clones the plan slide per option via `assembly.duplicate_slide`. A single-option proposal is unchanged in every respect, label included.
2. **Bidirectional cost ↔ impressions.** Cost was never an input at all — it only existed as a derived number in the preview, so "enter the cost, get the impressions" had nothing to type into. The grid now carries a Cost column with per-row driver tracking. This absorbed the old separate `Flat Cost` column.
3. **Drafted plans no longer invent products or misprice sports.** `sport:<key>` line products + a prompt that states there is no mandatory product + the draft clearing Section C's toggles before setting its own.
4. **One clarification round** after a draft, with hand-edited sections protected.
5. **TEGNA positioning toggle defaults OFF.**
6. **Audience finder and avails table work with no vertical selected.**

Then verified by driving the real app, which turned up four things the headless tests could not have (each documented in Key conventions above): duplicated slides colliding with retained slides' **partnames** (only reproducible against the real master deck); drafted **option names** being silently discarded by stale widget keys; a re-draft **dropping `agency_involved`** and repricing every line at net; and the drafted **budget being applied as a monthly rate**, doubling a two-month plan. End-to-end run: an NFL-only two-option draft ("Kickoff" $40K / "Championship" $75K, Jan–Feb) produced one NFL line per option at the $66 playoffs rate with no Premion line and Section C showing only Live Sports → NFL Playoffs; one clarification round moved the $2,500 production fee on top of each budget, landing Kickoff at $20,000/month and $42,500 for the flight (263,505 monthly impressions = 20000/(66×1.15)×1000) with a hand-edited client name preserved and reported; Generate assembled 23 of 119 slides including the extra option slide.

Covered by headless tests (not committed — written to the scratchpad): the bidirectional math in both directions incl. CPM edits, markup, flat-fee and zero-CPM rows; the budget waterfall tying exactly to target across flat/percent/split-evenly allocations; sports ratecard resolution; multi-option normalization and the option helpers; slide duplication verified on a synthetic deck (position, independent per-option fill with differing row counts, picture bytes intact through the rId remap); and the real form driven through `AppTest` (initial render, add/clone/cap/remove options, agency-toggle re-derivation, clarify-box gating across rounds).

**Supabase (phase 1 backend), done and verified live.** Schema in `supabase_schema.sql`, access in `db.py`, bootstrap in `setup_supabase.py`. Four tables plus a private `decks` bucket:

1. **`deck_versions`** — the master deck lives in storage; "exactly one active" is a partial unique index over the true rows only, so activation clears the previous active row first. The deck is fetched at generate time and cached with `@st.cache_resource` keyed on the version id, so it downloads once per session, not per generate; the on-disk copy is keyed on the version id too, so a fresh process reuses it and a newly activated version can't be served a stale file. Downloads land on a `.part` file first so an interrupted one isn't mistaken for a complete deck later.
2. **`products`** — 31 rows (10 media products + 21 Live Sports packages). Loaded at startup, cached with a TTL rather than for the process lifetime so a rate edit reaches a long-running session.
3. **`audiences`** (369 segments, 105 RFP-selectable) and **`audience_usage`** (3661 YTD delivery rows, one per segment *string* as booked — usually a combination rather than one catalog name, which is what makes it custom, the same rule the avails table applies).
4. **`proposals`** — every successful generate logs the whole form state, all options included, against the deck version it built from (`null` when that was the local fallback, so a logged proposal never claims a version it didn't use). Capture only; no browse UI yet. `db._json_safe` normalizes the numpy scalars and NaNs a Streamlit data editor produces, which jsonb would otherwise reject.

Verified against the live project: deck version 1 downloads from storage and resolves 119/119 with a full assembly off it; every product and sports CPM matches the ratecard exactly; the catalog is identical to the brochure PDF's on segment set, `rfp_selectable` and `times_used`; a real end-to-end generate through the form wrote a proposal row carrying `deck_version_id=1` and every plan option. Fallback verified too, by pointing the URL at a nonexistent project: all four loaders degrade, the form still renders, and exactly the two startup warnings show. **Test caches per process** — running a live AppTest and a broken-URL AppTest in the same process leaves `st.cache_data` state from the first contaminating the second (this produced a false failure once).

The master deck in storage is the optimizer's output (94.93 MiB → 47.75 MiB, +2.25 MiB of headroom under the 50MiB ceiling); `TEGNA_MASTER_DECK_v1_1.pptx` is unchanged and remains the local fallback.
